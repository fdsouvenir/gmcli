# gmcli v1.0.0 — Google Account pairing and OpenClaw 2.0

## Highlights

- Replace retired QR authentication with Google Account cookie input and
  phone-side emoji confirmation. `gmcli auth --cookies-file FILE` accepts
  private JSON or copied cURL input; `--cookies-file -` reads stdin.
- Refresh an existing pairing only for the same account and after a phone
  response. Use `--new` to deliberately create another pairing. Failed and
  cancelled attempts preserve the previous session, with atomic private writes.
- Update the Google Messages protocol library to v0.2608.0 and propagate
  cancellation through sync, history, send, reaction, and validation RPCs.
- Include v0.3.2's evidence-based connection health and update the archive
  skill to interpret it correctly.
- Require **OpenClaw 2026.8.1 (OpenClaw 2.0) or newer** for the ClawHub skill.
  Use supported frontmatter, a versioned Go installer, and a bundled runtime
  preflight. The skill keeps its archive queries read-only.
- Add usage exit code 2, explicit empty results in human-readable output,
  command examples, and `-v`/`--version` aliases.

## Breaking changes and upgrade

The auth interface changes from `gmcli auth` / `--qr-png` to private cookie
input with `--cookies-file`. This is a major version because callers must
update their authentication workflow. Usage errors now exit 2; operational
failures exit 1. JSON data shapes for archive queries remain unchanged.

Requires Go 1.25 or newer:

```sh
GOBIN="$HOME/.local/bin" go install github.com/fdsouvenir/gmcli@v1.0.0
clawhub update google-messages-local-archive --version 1.0.0
```

For a fresh OpenClaw skill installation:

```sh
openclaw skills install @fdsouvenir/google-messages-local-archive
openclaw skills check
```

Follow the [private Google Account pairing instructions](https://github.com/fdsouvenir/gmcli#pair-with-a-google-account).
Do not paste cookies into chat or execute the copied cURL command. The CLI
parses that text as data. Complete the displayed emoji confirmation on your
phone, then run `gmcli sync --follow` to populate or refresh the archive.
Existing local archives remain queryable while you migrate authentication.

Back up your database and session privately. When upgrading from before
v0.3.2, store-opening commands apply additive schema 4 without deleting
archive rows. JSON doctor prints its report and exits nonzero when issues
exist. Read-only protects against phone mutations, not local schema migrations.
Installing a binary does not restart an existing sync process.

## OpenClaw compatibility

The skill declares the 2026.8.1 minimum in descriptive metadata and enforces
it with a version-only preflight. OpenClaw 2026.8.1 has no native skill
minimum-version gate; unsupported metadata would not enforce the requirement.
The bundle passes that release's official skill validator. The ClawHub bundle
contains instructions, UI metadata, and the preflight script, never credentials
or message data. Its dependency installer pins gmcli v1.0.0.

## Validation and limits

Validation covers full Go tests, the race detector, `go vet`, a versioned
binary build, and offline CLI smoke checks with an isolated temporary store.
Authentication tests simulate success, same-account refresh, mismatched
accounts, invalid cookies, absent phones, wrong emoji, timeouts, and cancellation
without overwriting the saved session. Runtime tests cover minimum/newer,
older, prerelease, missing, unversioned, and failed version commands.

Real-phone pairing and reauthentication have **not** been exercised in this
release session. Automated protocol-wrapper tests do not prove live Google
service compatibility or a reconnected phone. Users must complete their own
Google login and phone confirmation. No messages or reactions were sent.

`recently_verified` remains bounded offline evidence, not proof of current
connectivity or complete historical recovery. A quiet phone may become
`unknown` after 15 minutes without observable archive evidence.
