# v0.3.2 — honest connection health (proposed)

Health-only beta patch for [issue #5](https://github.com/fdsouvenir/gmcli/issues/5).
This document prepares a release; it does not announce publication.

- Separate process heartbeat, transport, phone, archive-data, and validated
  snapshot evidence. Saved pairing and legacy activity are not health proof.
- Report bounded `recently_verified`, `unknown`, or `unhealthy` evidence. Empty
  snapshots against a populated archive remain unknown until corrected.
- Require new evidence after recoverable interruptions; latch terminal failures
  against late events. Ignore invalid data events.
- Return nonzero from JSON doctor when issues exist, while still printing JSON.
- Preserve archive rows with additive schema 4; do not promote legacy timestamps.
  Existing full schema-4 stores retain compatible evidence fields.
- Keep stale cached send settings distinct from a successful current refresh;
  preserve send/reaction safeguards and atomic session replacement.

## Installation after publication

Requires Go 1.25+. Once v0.3.2 is published:

```sh
GOBIN=$HOME/.local/bin go install github.com/fdsouvenir/gmcli@v0.3.2
```

Back up the database and session before opening them with the new version.
Store-opening commands apply migrations, including offline doctor. Use the
published module version, not a copied development executable. The operator
separately owns service restart and live validation; installing a file does not
change an already-running process. For rollback, retain the prior executable and
pre-migration store backup; this release provides no down-migration.

## Limits

No reconnection or live-phone validation is claimed. An otherwise connected quiet
phone may become `unknown` after 15 minutes because routine successful pings are
not all observable. No recurring network probes are added. A validated snapshot
proves visible inbox access, not historical completeness.

Google-account pairing and v0.4 remain separate in [PR #4](https://github.com/fdsouvenir/gmcli/pull/4),
including its mandatory real-device release gate. No new pairing command or skill
publication is included. Legacy skill health heuristics are outdated; consult
[connection health](../connection-health.md).

## Validation / handoff

`go test ./...` and `go vet ./...` cover temporary stores and synthetic events.
The PR records CI evidence. Maintainer review, merge, tagging, release publication,
versioned installation, and live service checks remain separate operator steps.
